# 多菜单 50 份初测与耗时参考标注（2026-11-15）

## 交付结果

已为当前可选 Aspose 或存在多条 Excel/Word 执行路径的菜单增加按功能区分的耗时参考。3-1 与 3-2 兼容项统一引用 mode 1 基准。保持既有选项编号、默认路由、文件选择、确认和业务规则；不根据速度自动切换引擎。

最终矩阵为 **18 个功能场景、87 条路径记录**：**63 条**通过前置正确性检查并完成真正菜单入口的 50 份测试，共 **3,150 份输出**逐份复核；**24 条**因能力、校验、对齐或实际路径观察门控而没有有效 50 份性能记录，不展示倍率。后者包含单份预检，不把“未建立 50 份样本”误称为完全未探测。

基于 main `34dfcd905b1157dca531908083b156b41f440a03` 的原有脏工作区。该 HEAD 保持不变，暂存区保持原样。没有提交、push、合并、打包或更新 dist，没有操作 Feature/Test 工作树。

## 菜单表现与范围

- 1-1 既有目标汇总写入；1-5 模板校验区域计算。
- 2-1 重复标记、2-2 删除重复、2-3 去重追加。
- 3-1 三引擎打印选择与 3-2 Rust 兼容显示，参考固定为 mode 1；没有把 mode 1 倍率冒充 mode 2/3 的实测。
- 4-4 Excel 转换/规范另存和 Word 转换；Excel 将 XLSX 与 XLS 分开显示，Word 当前为 DOC，DOCX 标待测。4-5 Sheet 改名、4-7 打开修复。
- 5-1/2/3/4/6/7；5-6 仅覆盖向既有目标追加的修改部分，新建仍用原 Rust writer。
- 7-1 既有配置修复，测试完成 y 确认和实际提交，不是仅生成候选后取消。
- 1-8 是全局策略设置，本身不处理文件，因此不给一个跨所有功能的统一倍数。在适用业务的“自动路由”一行，按当前全局策略显示该业务的已验证参考；未设全局覆盖时继续沿用原行为。
- 只有单一固定路径的读取、新建、文件归档/前缀操作等不强加 Excel 引擎比较；未启用的旧 UMYA 打印函数未恢复，5-8 未恢复。未测试的格式、路径不从其他路径借数字。

菜单将比值称为“参考耗时”：基准 1.00×；0.50× 表示耗时约一半，不是速度减半；数值越小，本样本耗时越短。所有数字注明 Windows Release、小型合成样本、50 份单轮初测。未通过/未测不填数字，评估水印提示保留。

普通修改与打印以 Openpyxl 为基准；1-5 以本机 Excel COM 为基准；转换以原 COM 路径为基准；4-7、5-4 保留原有定点路径作基准。不能让 Openpyxl 充当公式计算、Word 或所有原生补丁的基准。

## 测试口径

所有输入来自本轮 Python 合成夹具或从合成 XLSX/DOCX 经独立 Excel/Word 实例生成的旧格式副本；未读取或修改用户业务原件。每条路径使用同一 canonical 的独立副本。只关闭脚本创建的 Office 实例，无全局 kill、宿主软件安装/卸载或真实文件测试。

每条可用路径先跑单份对拍，随后完整运行一次 50 份，不用单文件乘 50，不对失败/缺输出做速度排名。不是中位数或统计稳定基准。OS 缓存未清空，机器后台负载未完全隔离；几百分点差异不能视为稳定优势。

最终公开的每个 PASS 记录均审查 EXECUTIONS.json：实际命令必须以 `menu` 进入，均含整个进程的启动到退出、真实引擎生命周期、读取、规划、保存、候选/源快照校验、提交和日志。输入选择/确认由脚本即时提供，不含人工等待。fixture 准备及对拍发生在计时外。

可以批处理的业务使用一次菜单调用处理 50 个目标/源文件；5-1 另有本期/上期参考文件；1-5 另有共同模板。5-7 是 50 对本期/上期、50 个修改目标，7-1 是 50 个配置任务；后两者当前只有单任务入口，使用 50 次真实独立菜单调用并累加实测耗时，明确标注，未扩大业务接口。

最早复用的脚本有部分 CLI 等价入口；它们的耗时未进入最终公开数值，已补测相应真实菜单。全局策略也通过相应菜单设置生效的同一环境状态进入实际业务，并要求日志确认预期模式和后端；50 份阶段必须观察到至少 50 笔完成路由。Auto 策略允许原有回退，但记录实际后端，不假冒单一引擎。

## 对拍与已知受限项

逐份检查值、类型、公式及缓存、合并、所覆盖的样式/尺寸、批注文本和作者、必要的页面设置及名称等。沿用此前比较器的有效默认值/列分组规范化，原始输出和原始快照保留，不是 ZIP 字节保真声明。Word 检查正文、表格、选定 run 样式、页眉页脚，并额外验证已知合成内容非空。

Aspose 的 Evaluation Warning Sheet、相关活动页变化和 Word 评估标记是用户已接受的例外，只从校验视图排除；输出文件没有删水印。时间包含实际生成评估标记的成本。其他原生新建汇总输出不因上游使用 Aspose 而自动带 SDK 水印。

COM 的 Calibri/宋体与默认行高 15/13.5 归一化按已确认的外观例外单列。最终重新审查了全部实际例外，只允许这两个具体差异，不笼统忽略所有字体属性。Aspose 的 XLSX 转换还要求与源文件语义一致，未复制 COM 的外观变更。

1-5 的 BetterOffice 保留 `'数据'!`/`'参数'!` 引号，而 COM/Aspose 对合法标识符省略引号。仅在测试视图中对这两个已知 Sheet 的 RANGE token 规范化，不碰字符串字面量、不修改输出公式；所有 50 份 D2 必须为“通过”、E2 必须为数值 30，原模板中故意错误的 -999 缓存未修改。

**带批注 XLS→Aspose 预检失败**：现有结构校验报告“改变合并区域或批注：数据”，没有发布结果。未放宽校验、未关闭既有 XLS 入口，也未伪造 50 份速度。该项需要后续单独区分 XLS 读取补充能力、候选验证与 SDK 行为；本任务未擅自修复业务路径。菜单显示样本未通过，原 COM 的 50 份结果保留。

其余受限项详见 COMBINED_RESULTS.json 的 user_reason_excerpt、原始 stderr 和 DIFFERENCES。GATED 既可能是明确不支持某个计划/保留要求，也可能是结果未对齐，不一概说成库不支持。受限路径保留原选项，不自动回退或关闭。
