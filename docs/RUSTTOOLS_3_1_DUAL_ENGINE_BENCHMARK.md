# rustTools 3-1 双引擎性能 Benchmark 报告

数据：`results/benchmark.json`（30 条，2 引擎 × 3 规模 × 5 次重复）。
口径：**菜单端到端墙钟**（含菜单进程启动、配置读取、源工作簿读取、样式读取、区域提取、
目标工作簿创建、数据写入、页面设置、保存——完整生产路径，非仅内部写入函数）。
每次重复前清理输出文件，避免「目标已存在」快速失败污染数据。
日期：2026-11-11。

## 1. 批量性能（菜单端到端墙钟，毫秒，5 次取中位）

| 引擎 | 10 簿 | 50 簿 | 100 簿 | P95(100) | min | max |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Openpyxl | 1678 | 16674 | 71933 | 72774 | 70566 | 72774 |
| **Rust** | **233** | **451** | **699** | 851 | 584 | 851 |

全部 30 次运行 exit=0（无失败）。

## 2. 加速比（Rust vs Openpyxl，墙钟中位）

| 文件数 | 加速比 |
| ---: | ---: |
| 10 | **7.20x** |
| 50 | **36.97x** |
| 100 | **102.91x** |

加速比随规模扩大——Openpyxl 的 Python 启动 + 双份源簿加载成本随任务数线性累积，
而 Rust 常驻单进程批量处理摊销了全部固定成本。

## 3. 输出文件大小

| 文件数 | Openpyxl | Rust |
| ---: | ---: | ---: |
| 10 | 18.0 KB | 18.0 KB |
| 50 | 72.5 KB | 69.2 KB |
| 100 | 140.7 KB | 133.3 KB |

Rust 输出略小（无 sharedStrings 冗余、更紧凑的样式表）。

## 4. 峰值内存

Rust 引擎批量 100 簿在单进程中处理（常驻），峰值内存约 40–90 MB（与通用引擎
Benchmark 中 rust writer 的量级一致）。Openpyxl 路径为多进程（worker 每任务一次），
单进程峰值 26.9 MB 但总 CPU 时间更高。

## 5. 各阶段耗时（Rust 引擎内部）

基于代码结构与此前通用 Benchmark 的阶段性测量：
- 配置读取（calamine）：毫秒级
- 源工作簿读取（calamine + OOXML 样式窄解析）：主要成本，随源文件大小线性
- 区域提取与重组：微秒级（内存操作）
- rust_xlsxwriter 写出：毫秒级
- 端到端瓶颈在源簿 I/O 与 XML 解析，与 openpyxl 的差异主要来自
  Python 解释器开销 + 双份工作簿加载（openpyxl 脚本每簿加载两份）

## 6. 与通用修改引擎 Benchmark 的关系

上一轮通用 Benchmark（打开→修改→保存既有工作簿）不能外推到 3-1：
- 3-1 是「读取源区域 → 重组 → 新建工作簿」，落在 rust_xlsxwriter 的写入强项区
- openpyxl 在 3-1 中的成本主要是「双份源簿加载」而非「修改」
- 本轮实测的 103x 加速比（100 簿）是 3-1 专属工作负载的真实结果

## 7. 测试环境

- Windows 11 x64，rustc 1.99.1（release），openpyxl 3.1.5（随包 Python 3.12.10）
- rust_xlsxwriter 0.98.2、calamine 0.37.0、rxls 0.1.4（未用于 3-1）
- 夹具：每簿 30 行 × 4 列 + 合并标题 + 百分比格式 + 批注，30 行/簿 × N 簿
- 原始数据：`results/benchmark.json`（30 条逐 rep 记录）

## 8. 口径说明

- 墙钟含菜单进程启动（Rust 二进制约 5ms；Openpyxl 路径含 Python worker spawn）
- 每次重复前清理输出文件，避免「目标已存在」快速失败
- 未计入：人工打开 Excel 验证的耗时；PDF 导出时间（另行冒烟，均 <1s/文件）
