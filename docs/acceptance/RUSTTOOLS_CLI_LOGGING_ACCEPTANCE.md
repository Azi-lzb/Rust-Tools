## 异常与日志展示发现

1. 地区总分校验区分了“检查执行失败”和“检查成功但发现差异”。100 个样本的摘要为 99 成功、1 失败、1 项业务差异，业务异常没有被算成失败文件。
2. 损坏 xlsx 可定位到 `broken.xlsx` 与 `workbook_read` 阶段，并显示 ZIP 读取原因。该错误链重复表达了 `Could not find EOCD`，长度偏长，建议后续统一缩短用户摘要、在开发者日志保留完整错误链。
3. 大批量选择现在列出最多 5 个可区分文件名，并说明其余数量；正常处理路径不再反复打印绝对源路径。
4. 100 文件真实菜单没有逐工作簿打印正常完成消息，按 10% 左右输出检查点；业务差异与读取失败仍立即显示。
5. 最终摘要仍包含 run_id、详细事件 JSONL 相对位置和统一 JSON 记录名。它们便于故障追踪，但不是理解业务结果所必需；本轮未删除。
6. 报表输出路径给出完整路径，便于定位。动态刷新能力未实测；当前样例使用逐行检查点。

## 第二轮日志优化（2026-11-05）

第二轮在第一轮成果上继续收敛，不改变业务逻辑与结构化事件格式：

1. **最终摘要多行分组**：`format_terminal_summary_with_outputs` 重写为状态头/输入统计/业务指标/需要关注/输出结果/耗时六组；空组整体隐藏，零值指标不再打印。
2. **逐行日志级别**：`summary_line_level` 让输出路径与统计行在部分失败时保持 INFO/WARN，仅错误明细行为 ERROR；框架线（`====`、空行）不带级别前缀。
3. **错误链去重**：`summarize_error_message` 把同一原因的重复链压缩为一次出现，完整链仍保留在结构化事件中。
4. **用户视图精简**：run_id 与统一 JSON 记录名移出用户终端（保留「详细日志」指针）；region-sum 的业务模块完成行不再与统一摘要重复打印。
5. **短任务节流**：`BatchLogPolicy::with_elapsed_ms`——运行不足 0.8 秒时常规检查点只保留首尾；8 个功能事件入口均已接线。
6. **off 视图静默**：转换/批量重命名/村镇银行拆分等入口在 off 视图不再漏出分组摘要；developer 视图保留机器 JSON。
7. **名称统一**：菜单横幅、CLI 头、配置错误文案改为 rustTools；`PyTools_专用报表处理结果` 目录名与 Cargo 包名等内部标识暂不改动。
8. **2-3 路径集中**：写入过程行去掉绝对路径，目标路径仅在「目标工作簿」行展示一次；打印流程非交互分支的「处理中...」占位行删除。
