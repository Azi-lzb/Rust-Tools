执行者：Codex（pytools-dev）
目的：修复 PT-4-8 局部文件名映射与当前 PyCode 的 Pandas 缺失值语义不一致。

发现：只读调用原 Python _load_file_local_rename_map 读取原项目 config.xlsx，返回 61 条映射。Rust 共享 reader 导出同一工作表的 M/N 表头及空列，但 Rust 业务层把缺失单元格映射为空字符串，最终错误报告配置缺少规则。原 Python 使用 pandas.read_excel(dtype=object)，配置表其余列将 DataFrame 行延伸至 61 行；M/N 空值变为 NaN，Python _norm 直接 str(value).strip()，得到字面字符串 nan。因此原 Python 的 61 条规则为 nan→nan，批处理继续执行而非报错。

实现：pytools-core/src/local_filename_map.rs 的 PT-4-8 配置转换对缺失、Empty 及零长度字符串映射为 nan，其他值沿用原转换；未修改共享 Excel reader、Cargo 文件或源 Python 项目。新增集成回归覆盖空源、空目标、空规则行及文件内容保留。

基线修正：原 local_filename_map_48_python_baseline.json 声称空目标删除片段，与当前只读 PyCode 实际执行不符。用原函数重跑后将 prefix_.doc 修正为 prefix_nan.doc，统计仍是 ok=5、skip=5、rules=6。新增 pandas_empty_config_cells 基线：ok=2、skip=1、rules=4，最终文件名及内容与 Rust 回归一致。
