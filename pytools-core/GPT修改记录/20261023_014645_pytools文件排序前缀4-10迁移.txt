目的
----

迁移行为
--------
- 配置仍从“文件排序配置”读取；没有有效规则时返回与源实现一致的错误。
- 文件名直接以某个排序前缀加下划线开头时，直接移除排序前缀，不读取工作簿。
- 排序前缀位于内容前缀之后时，按 `重命名配置!O:P:Q` 的唯一启用规格，用共享 Calamine reader 读取内容；仅当实际内容前缀与文件名前缀一致时移除排序段。内容配置缺失/无效、工作簿读取失败或内容不匹配时按源逻辑跳过内容分支。
- 文件名冲突时增加 `_1` 等后缀，不覆盖已存在文件。报告生成失败时从记录的目标回滚本轮改名。
- 以共享 rust_xlsxwriter 新建“取消文件排序前缀结果”报告。该 API 没有 COM/Office 依赖。

未完成与风险
------------
- 候选 API 尚未接入产品菜单/CLI，不代表整个 4-10 功能已迁移或验收，也不改变生产路由。
- 内容单元格只在合成 XLSX 上对拍；`.xls` 内容读取、`.xlt`、日期单元格、公式缓存值、多单元格规格和真实模板仍未验证。测试中的 `.xls` 是不含工作簿的文件名改名前缀样本，不证明 BIFF8 内容读取。
- 尚未在真实目录、Windows 原生 Rust、麒麟 V10、统信 UOS、glibc 2.28 或离线 deb 上验证。硬链接不受支持的文件系统上会安全报告该次改名失败并保留源文件。
