# py_statistics_tools Rust 迁移计划

## 范围与约束

- 行为基线是 C:\Users\AZI\Desktop\VibeCode\4.pytools-main 中的 PyCode 项目；源目录只读。
- NoComPyTools 是同一交付目标中的独立变体参考。先盘点与 PyCode 的共有和独有行为；独有行为标待确认，不能静默遗漏，也不单独生成第三个产品。
- 只迁移业务行为和必要配置契约；不迁移 Python 菜单实现、PyInstaller、虚拟环境或 Python 运行模式。
- 工作表提取按不带批注的普通版；COM 批注提取分支不迁移。
- 主路径使用 Rust；既有工作簿由 ExcelEditPlan/ExcelModifier 统一边界处理。OOXML Patch、umya-spreadsheet、Go Excelize worker 按真实模板、整批操作、保真度、性能和维护成本评估，不预设固定优先级，也不要求三者全部实现。
- 公式重算默认关闭，需要时才显式调用 sidecar/lo-convert。格式转换只保留同类转换，首批 Excel .et→.xlsx、Excel .xls→.xlsx、Word .doc→.docx。PDF 导出和跨类别转换不在范围内。
- 打印工作流仅写页面设置并准备工作簿，不渲染、不导出 PDF。
- Excel 原语与跨产品复用能力经 workspace crates/ 下的共享库提供，不依赖 audit-core；通用第三方 crate 在 workspace 根 Cargo.toml 管理版本。

## 本轮用户指定范围

本轮优先完成 pytools 的 Rust CLI 业务实现；按用户最新范围纳入：

- 时序工具：1-1 表头路径比对、1-3/1-4 两种宽表汇总、1-5 预校验；不包含 1-2 时序提取。
- 去重工具：全部六项（按批注检查/删除、按配置检查/删除/追加、按配置预校验）。
- 打印工具：3-1 至 3-4（批注保留格式、批注快速复制、配置打印、配置预校验）；不包含 3-5 PDF。
- 转换工具：4-1 至 4-10（包括同类 Excel/Word 转换、工作表名、文件名、提交检查、排序前缀和撤销）；不包含 4-11 Python 模式切换。
- 配置工具：5-1 初始化/修复、5-2 查看当前配置。
- 汇总工具：6-1 使用区域汇总、6-2 批注汇总。
- 一二批工具：7-1 至 7-8 全部业务项，包括机构名称标准化；工作表提取按不带批注普通版。
- 归档工具：8-1 至 8-5 全部预览、执行和直接复制项。
- 快捷工具：9-1 至 9-3 打开配置、output 最新文件和 output 目录。

每项功能在迁移时先完成相关 crate 编译、范围内单测、最小 CLI 冒烟、实际入口接线和必要的文件安全检查，并更新迁移状态；合成对拍可用于推进逻辑，但须标明样本性质。所有约定功能都具备可运行 CLI 后，再进入 Windows 集中验收，执行真实样本 Python/Rust 对拍、集成/回归测试和缺陷修复；全部关键 Windows 业务通过后，再集中完成 Linux 离线 deb 验收。测试未完成前不得把功能标为验收通过或启用未经验证的 Excel 修改后端。原 Python 菜单、整套 COM 业务工作流、PDF 及 Python 模式切换不进入生产路径；未来只允许按 workspace 规则显式接入已验证的 Windows ExcelModifier COM 编辑和独立 ExcelCalculator 计算能力。

1. **逻辑基础**：盘点已迁入的日期解析、路径映射、规则筛选和配置类型，与源实现逐项核对边界及错误行为。
2. **格式与配置**：完成 xls/xlsx/xlsm/xlsb/csv 输入矩阵和 .et 转换契约；迁移配置读取、初始化、修复、预校验和映射规则。
3. **时序、汇总与去重**：实现时序提取、表头路径比对、宽表汇总、批注/配置去重、追加、使用区域汇总和批注汇总。
4. **业务批处理**：实现村镇银行拆分、机构名称标准化、外资行行删除、外汇页眉修改、地区总分校验、普通版工作表提取、涉农贷款月度及季度调整核对。
5. **打印、转换与文件操作**：写入已确认的页面设置；迁移批量重命名、Sheet 重命名、内容映射、提交缺失检查、排序前缀、归档预览/执行和快捷文件操作。按显式用户触发调用允许的同类转换 sidecar。
6. **CLI 与交付准备**：用 Rust CLI 提供迁移后的工作流；删除 Python 专属模式切换；保持独立 probe、fixtures 和报告。Windows 真实验收完成后，再按 workspace 集中 Linux 阶段构建单独 pytools.deb 并执行 glibc 2.28 与目标环境验收。

## 验收

- 每项功能登记输入格式、配置项、输出契约、保留项和状态；未验证行为不能算迁移完成。
- fixtures、probe 配置和报告只放 pytools-core/，不得与 audit-core 共用业务样本或报告。
- 用户样本缺失时使用合成样本推进纯逻辑和探针，但报告明确区分合成结果与真实模板验证。
- 对拍基线优先使用 Rust probe；只有 Rust 无法读取或断言某项属性时，才在测试辅助中使用 Python/openpyxl。
- 性能结论必须来自同机、同输入、同契约的实测；未测量明确标记。
