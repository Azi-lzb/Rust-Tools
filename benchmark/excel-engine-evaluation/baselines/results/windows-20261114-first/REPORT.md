## 公式降级与修改能力

- XLS 合成夹具的 4 个公式具有经 BIFF 字节确认的空缓存；Rust 明确 UNSUPPORTED，无输出且输入不变。Aspose 显式 CalculateFormula 后缓存为 [8, 68, 6, 5]，公式仍保留：EXPECTED_CAPABILITY_GAP。未声称 Aspose 打开/保存必然自动计算，也没有给 Rust 添加计算器。
- 另有独立的 UNEXPECTED_PARSER_DIFFERENCE：calamine 0.37.0 对该 XLS 的跨表公式解码与已确认的源公式不符（出现错误工作表/坐标）。它不能归入“预期计算缺口”。实验适配器因此拒绝所有 XLS 公式，不宣称有缓存时即可保留其文本；主项目依赖及生产路由未改。原期望与解析文本保存在能力报告。

差异分类与结论：

- openpyxl：本夹具选定语义均符合预期，但不透明 customXml 被丢弃。
- UMYA：数据验证的 formula1/formula2 上下限丢失，属于实际结构/规则变化；另有列宽补写、Sheet 引用引号变化，后者为等价表达。
- Aspose：默认行高显式化、命名引用引号、RGB alpha、验证默认 between 编码、空公式缓存类型编码等变化；不应把所有差异条数都叫作数据损坏。customXml 仍丢失，评估 Sheet 过滤后仍有整簿重写。
- Aspose 相对自身 no-op，过滤评估 Sheet 后的单值修改仅改变对应工作表，样式修改改变工作表和 styles；这描述其序列化基线，不能证明原始包精确补丁能力。
- ooxml-patch 页眉替换：只有目标 worksheet 部件变化，其他全部未压缩部件哈希不变，语义检查通过。该结论仅针对本窄操作和夹具。

原始部件增删和未压缩 SHA256、规范化 XML差异、评估过滤视图以及 Aspose 相对自身 no-op 的原始/过滤差异见能力 report.json。语义项包括值/类型/公式、缓存编码、合并、批注、链接、数值格式、加粗、填色、行列尺寸、命名区域、打印和页眉页脚/数据验证；不是覆盖所有 Excel 对象的通用保真认证。不透明 customXml 部件的丢失不可归因于水印。ooxml-patch 仅做它实际支持的页眉替换，不伪造通用单元格修改能力。
